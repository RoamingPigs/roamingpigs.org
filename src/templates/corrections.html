Corrections

What I got wrong, and when I fixed it

A record that cannot be corrected cannot be trusted. Each entry says what was published, what was wrong and what replaced it.

Log

  1. 12 October 2026

    An ellipsis counted as text, the codec description was wrong, and the generator was missing

    A review of the full run found three things I had stated too strongly or had left out.

    • “Wrote words.” The plan counts any non-empty normalised output on a non-speech clip. The normaliser turns an ellipsis into a full stop, so eight outputs that were only “...” counted as text: seven from one model and one from another. This site said every model wrote words on every clip. It now says “returned text”, and gives the stricter rate, which counts only outputs with a letter or digit. The plan’s rate, and every number derived from it, is unchanged.
    • Codec description. The dataset card said G.711 used ffmpeg. It uses Python’s audioop companding. It also did not say that every narrowband path is band-passed to 300 to 3400 Hz before coding, so a narrowband result combines band-limiting and the codec. The card and this site are corrected. The audio files did not change.
    • Generator. The code that made the audio was not in the public repository, although a page implied it was. It is now in the generator directory. I ran it, and every one of the 1,050 files matched its published SHA-256. It was added after the full run, so its commit is later than the plan’s.
  2. 11 October 2026, later

    The pilot speech results were replaced by a full run, and the dataset card was corrected

    The 10 October pilot scored 5 calls, not the 40 in the released dataset, on audio generated at a different speaking rate. It capped output at 48 tokens and gave no intervals. It also padded audio features to the longest clip in each batch. I then found that this made the text depend on batch composition: with that padding, about half of 24 test clips changed when the batch size changed. With the standard padding they did not. The pilot figures are removed from the records and replaced by a full run on the released files, with intervals and a plan written first. The pilot files stay in the results list marked superseded.

    • Hugging Face card. It listed apache-2.0 for the dataset while the manifest says CC BY 4.0 for the audio. It described the data as drawn from “operational” Navy, Coast Guard and DHS profiles and as “expert-generated”. The speech is text to speech and the profiles are my own models. The card is rewritten to say so.
    • Code link. The first version of this site linked to a GitHub repository that did not exist. It now exists, with the code and the plan.
    • Energy figure. The third wall-meter run is excluded because its recorded speed implies more memory traffic than the bus can carry.
  3. 11 October 2026 Pacific

    Energy estimators and annotation provenance clarified

    The energy headline previously called mean power divided by decode speed a meter reading and treated the first reported integrated-energy value as a peak-power ratio. Those quantities use different estimators and may use different windows. Raw timestamped power arrays are absent from the historical file, so the integrated value remains an unreconciled report. The chart now labels the ratio as an estimate. The bandwidth screen is a calculator assumption, not proof a measurement is wrong.

    The Echo aggregate now comes from its original development record. The separate MAST file is explicitly labeled programmatic annotations and allocated resources; its coder agreement is not independent annotation reliability. Existing numbers are retained as historical data, with their corrected interpretation.

  4. 11 October 2026

    The first version of this site was withdrawn and rebuilt

    The first version went live on {{ v.first_pub }}. {% if v.first_pub == site.modified_human %}Later that day{% else %}On {{ site.modified_human }}{% endif %} I checked every figure and identifier on it against the results files and removed what I could not trace.

    • Identifiers. A DOI and an organisation registry link were shown for work that had never been deposited. Neither existed. They are gone, and these records carry no DOI.
    • “Merkle root”. The digest shown was the SHA-256 of a single audio file, not a root over the dataset. There is no combined digest yet, only one per file.
    • Word error rates by codec. Five values with confidence intervals appeared in no results file. They are replaced by the means in the E2 ledger, as point estimates.
    • Agent coordination panel. The “12,400 holds” and “0.00% collisions” figures had no source, and an 84.7% consistency figure was another experiment’s routing accuracy. The record now shows the 16-attempt diagnostic.
    • Error correlation. A value of 0.42 matched no statistic. The simulated correlation is {{ v.rho }}, and the record now says it is a simulation.
    • Energy per token. A figure of 1.66 J came from dividing an assumed power by an assumed speed. Power/rate estimates from reported summaries range from {{ v.j_min }} to {{ v.j_max }}; those ratios are not direct energy meter readings.
    • Dataset description. The files are 16 kHz with {{ c.trcs.conditions }} conditions, not 8 kHz with 30.
    • Labels. “Proven”, “empirically verified”, “gate cleared”, “6/6 pass” and an RFC-style header implied a reviewer and a standards body. There is neither. They are removed.
  5. 10 October 2026

    Write-up of the silence experiment disagreed with its results file

    The prose summary of the first experiment said an energy gate removed 90 to 100% of invented words. The results file shows {{ c.e1.gate_suppression_pct_min }} to {{ c.e1.gate_suppression_pct_max }}%, and no effect on noise or squelch. The results file is right. This site uses it.

How corrections work #

I fix errors in place and log them here with the date. I do not change a figure silently. If a correction changes a conclusion, the record’s evidence mark changes too.

To report an error, use the contact page and name the record.
